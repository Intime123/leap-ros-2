> 架构背景见 `10_项目总览与架构.md`；每阶段完成后的总结模板见 `template_phase.md`。

> 工作方式：**每完成一个阶段 → 按模板写 `docs/NN_阶段名.md` → commit + 打 tag** → 找我总结复盘。

## 使用规则

1. 一个阶段 = 一个可独立验收的能力增量，做完立刻写阶段文档，不要攒。
2. 阶段文档命名沿用 README 规划：`docs/02_固件烧录与agent连通.md`、`docs/03_工作空间编译与bringup.md`……
3. 每阶段提交后打 tag：`git tag -a phase2-connect -m "..." && git push origin phase2-connect`。
4. 「验收标准」不过夜：宁可拆阶段，不要自欺欺人往下走。

## 阶段 2 · 固件烧录与 agent 连通 ✅（2026-10-17 完成，完整留痕见 `02_firmware_build.md`）

### 版本决策（面试重点）：实编译实验判定 v6.1 不兼容 → v5.5.3 定版

- **实编译实验判定**：先在 v6.1 下真实编译 → 配置阶段报 `Failed to resolve component 'json'` + legacy I2C API 冲突，实证 cJSON 移除、driver 拆分等破坏性变更 → 迁移 v5.5.3（与上游教程一致），不做无谓硬移植。
- **上游构建残留清理**：`dependencies.lock` / `esp32_toolchain.cmake` / `micro_ros_dev/` 等含 5280 处 `/root/maturo_project/...` 绝对路径，任何人 clone 必踩；清理步骤已沉淀（可回馈上游 ISSUE）。
- **主机端依赖链**：catkin_pkg / `empy==3.3.4`（4.x API 不兼容 rosidl）/ lark 装入 v5.5.3 venv。
- v6.1 已删除（`eim list` 仅 v5.5.3）；判定实验全部证据留存于 `02_firmware_build.md` 问题表——排障过程本身就是面试素材。

### 烧录与 agent 连通（2b ✅，复现步骤）

```bash
# 0) 串口权限（一次性）
sudo usermod -aG dialout $USER     # 必须注销重登录才生效，用 groups 自查

# 1) 烧录（v5.5.3）
source ~/.espressif/tools/activate_idf_v5.5.3.sh
idf.py -p /dev/ttyUSB0 flash monitor   # 首次若 No serial data received → BOOT+RESET 手动进下载模式

# 2) agent 与验证
source /opt/ros/jazzy/setup.bash && source ~/microros_agent_ws/install/setup.bash
ros2 run micro_ros_agent micro_ros_agent udp4 --port 8888 -v6
ros2 node list                  # /leap_low_driver
ros2 topic hz /odom             # ~50 Hz；/imu ~50Hz；/scan /battery_state /ultrasonic ~10Hz
ros2 topic pub /cmd_vel ...     # 能动车（先架空车轮）
```

**实测**：烧录 2026-10-17 16:10 成功；agent 连通 16:56，五话题 `/odom /imu /scan /battery_state /ultrasonic` 上线（Wi-Fi 手机热点 2.4GHz）。

**关键细节**：
- 首次上电无 Wi-Fi 记录时固件进配网模式（SoftAP + HTTP 配网页），填路由器 SS/密码；agent 地址默认 `192.168.31.214:8888`，网段不同必须在配网页修改（存 NVS）。
- 排障顺序：`ros2 node list` 空 → monitor 日志看 Wi-Fi 连接 → 查 agent IP/端口 → PC 防火墙 → 用 `microros_uart` 模式隔离 Wi-Fi 因素。

**验收清单**：✅ 全部通过（实测记录见 `02_firmware_build.md` 验收段）。
**交付物**：`docs/02_firmware_build.md`（六段式留痕：判定实验 / 问题表 / 实测数据 / 烧录连通记录）。
**知识体系**：串口权限与 dialout/udev；Wi-Fi SoftAP 配网与 NVS 持久化；micro-ROS 传输层（自定义 UDP/UART）与 XRCE-DDS 会话；QoS 匹配；ROS2 调试工具链。
**常见坑**：`usermod` 不重登录不生效；PC 与固件网段不一致；烧录后自动 reset 进 app，日志走 UART0。
**简历子弹**：打通 micro-ROS 全链路，`/cmd_vel` 下行与 `/odom`(50Hz)/`/imu`(50Hz)/`/scan`(10Hz)/`/battery_state`(10Hz)/`/ultrasonic`(10Hz) 上行。

## 阶段 3 · 工作空间编译与 bringup

```bash
# 一次性：上游工作空间放进 ~/robot_ws（本机已建好空目录）
cd ~/robot_ws/src

# 若实际编过，在阶段文档记录实测结论（这是面试好素材）

# 终端 A：bringup（odom→tf + robot_state_publisher）

# 终端 B：键盘遥控

ros2 launch xuegecar_description display.launch.py
ros2 run tf2_tools view_frames        # 导出 TF 树 PDF 存档

```

- **标定逻辑**：编码器脉冲→线速度系数；轮距 131.7 mm 已固定；先标速度环 PID（阶跃响应看超调/静差），再验证位置环。
- **验收**：TF 树 `odom→base_footprint→*` 完整；RViz 模型与实物一致；直线 1 m 误差 <5%；旋转 90° 误差 <3°。
- **交付物**：`docs/03_工作空间编译与bringup.md` + TF 树图 + RViz 截图入 `media/`。
- **知识体系**：colcon overlay 与 `--packages-select/skip`；launch 系统（Python launch、Node/IncludeLaunchDescription/TimerAction）；TF2 坐标系树与 `odom→base_footprint` 语义；差速运动学（v=(vR+vL)/2，ω=(vR−vL)/track）；Odometry 与漂移；PID 阶跃响应整定。
- **常见坑**：bringup 未起导致 TF 断链、RViz 报错；`/odom` 与 `/cmd_vel` 方向相反（符号）；gmapping 包在 Jazzy 的编译问题（先 skip，记录实测）。
- **简历子弹**：完成差速底盘运动学校准与 PID 整定（直线误差 <5%），搭建 `odom→base_link` TF 与 RViz 可视化链路。

## 阶段 5 · 自研避障节点（C++ rclcpp）★ 简历差异化阶段

> 上游只提供「配置好的 Nav2」；自己写避障节点是把「我会用」变成「我理解并能实现」的分水岭，也是本项目与「纯复现」拉开差距的核心证据。

- **目标**：不依赖 Nav2，用自己的 C++ 节点基于 `/scan` 实现「前进—避障—转向」行为。
- **建议实现路径**（由浅入深，每步可独立提交）：
  1. 骨架：`src/leap_obstacle_avoidance/` 建 ament_cmake 包，rclcpp 节点订阅 `/scan`、发布 `/cmd_vel`，20 Hz timer 驱动决策；
  2. 感知处理：将 360 点按扇区聚合（如前 ±30°、左右 30–90°），取最近障碍距离；
  3. 决策：阈值状态机（畅通→前进；近障→减速；受阻→原地转向最空旷扇区），带指令超时与急停；
  4. 增强（可选）：简易 VFH（直方图投票）或势场法转向质量评估；
  5. 测试：`ros2 bag` 录 `/scan` 回放回归；布置固定障碍场景量化成功率。
- **验收**：固定障碍场景连续 10 次无碰撞通过；松手/超时后 1 s 内停车；代码有 README 说明算法选择与参数。
- **交付物**：`docs/05_自研避障节点.md` + 节点源码 + 测试记录（bag + 成功率表）。
- **知识体系**：rclcpp（Node/Subscription/Publisher/Timer/参数）；激光数据扇区聚合与特征提取；避障算法谱系（Bug 算法/VFH/势场/DWA 的思想与取舍）；状态机设计；与 Nav2 的边界（何时该用工业方案）。
- **常见坑**：`/scan` 的 `frame_id` 与底盘坐标变换；决策频率与雷达频率不匹配导致迟滞；与 teleop 争抢 `/cmd_vel`（约定优先级/互斥）。
- **简历子弹**：自研 C++ 避障节点（rclcpp），基于激光扇区聚合 + 阈值状态机实现前进/避障/转向决策，固定场景 10/10 无碰撞通过。
