## 阶段 2 · 固件编译、烧录与 agent 连通 ✅（摘要，完整见 `02_firmware_build.md`）

### 目标

1. 判定本机 ESP-IDF v6.1 能否直接编译上游固件
2. 不兼容则迁移至教程一致的 v5.5.3 并编译通过
3. 烧录上板，micro-ROS Agent 连通，话题上线

### 关键决策（面试重点）：实编译实验判定版本，而非猜测

先在 v6.1 下真实编译 → 配置阶段即报 `Failed to resolve component 'json'`，叠加 legacy I2C API 冲突，实证 6 类破坏性变更（cJSON 移除、driver 拆分、mcpwm 字段删除、枚举更名、日志宏更名、头文件归属变化）→ 评估修复成本后决策迁移 v5.5.3（与上游教程一致），不做无谓硬移植。v6.1 已删除（`eim list` 仅 v5.5.3，2026-10-17 16:04）；判定实验的全部证据留存于 `02_firmware_build.md` 问题表。

### 问题与解决（精选根因链，全表见 `02_firmware_build.md`）

| 问题 | 原因 | 解决 |
|---|---|---|
| v6.1 配置失败：json 组件缺失 | IDF v6.0 移出 cJSON 组件 | 判定不适配，迁移 v5.5.3 |
| 编译找不到 `/root/maturo_project/...` | 上游提交了作者机器构建残留（5280 处绝对路径：lock / toolchain / 预建环境） | sed 替换 + 删生成物重建 |
| std_srvs AttributeError | empy 4.x 与 rosidl 模板引擎不兼容 | pin `empy==3.3.4` |
| 桌面副本 `address-of-packed-member` 报错 | zip 旧 sdkconfig 未关默认 `-Werror`，GCC14 对 MAVLink packed 成员必报 | sdkconfig 开 `CONFIG_COMPILER_DISABLE_DEFAULT_ERRORS` |
| 烧录 `No serial data received` | 固件已占串口 / 未进下载模式 | BOOT+RESET 组合键手动进下载模式 |
| 串口无权限 | 用户不在 dialout 组 | `sudo usermod -aG dialout $USER` + 重登录 |
