# 01 · 项目总览与系统架构

> 本文是「认知层」：回答 leap_ros 是什么、由什么组成、数据怎么流。

> 所有技术参数均注明源码出处；无法从源码确证的标注「推断」。

## 1. 一句话定位

LEAP ROS2 是一个 BOM 约 200 元的开源差分底盘机器人：**ESP32-S3 跑下位机固件（ESP-IDF + micro-ROS）**，通过 Wi-Fi 与 PC 上的 **ROS2（Jazzy）** 通信，支持遥控、SLAM 建图与 Nav2 自主导航，面向教学、竞赛与二次开发（上游 README：交流 QQ 群 1055265929，飞书文档 + B 站视频配套）。

## 5. 数据流全图

**下行（控制）**：`/cmd_vel`（`geometry_msgs/msg/Twist`，sensor-data QoS）→ WiFi UDP → `microros_task` → 队列 `q_motion_cmd` → `motion_task`（20 ms）→ `motion_controller`（差速运动学 + 速度/位置 PID 双环）→ `motor_driver` PWM → TT 电机；`encoder_driver`（PCNT）反馈轮速，构成闭环。

**上行（感知）**，全部由 micro-ROS 发布（节点名 `leap_low_driver`，定时器 20 ms）：

| 话题 | 类型 | 频率 | frame_id | 数据来源 |
|---|---|---|---|---|
| `/odom` | `nav_msgs/msg/Odometry` | 50 Hz | `odom` → `base_link` | 编码器 + 运动状态 |
| `/imu` | `sensor_msgs/msg/Imu` | 50 Hz | `imu_link` | LSM6DS3 |
| `/scan` | `sensor_msgs/msg/LaserScan` | 10 Hz | `laser_frame` | Camsense（360 点 / 1° / 0.02–12 m） |
| `/battery_state` | `sensor_msgs/msg/BatteryState` | 10 Hz | `battery` | ADC |
| `/ultrasonic` | `sensor_msgs/msg/Range` | 10 Hz | `ultrasonic_link` | HC-SR04 |

服务：`/set_speed_pid`、`/get_speed_pid`（`leap_interfaces/srv/*.srv`，参数写入 NVS）。
单位约定：固件内部 mm / mm/s，ROS 侧 m / m/s（`doc/protocols.md` 单位表）。

## 6. 通信协议矩阵（固件同时只启用一种，NVS 保存）

| 模式 | 传输 | 关键参数 | 典型用途 |
|---|---|---|---|
| `micro_ros`（默认） | Wi-Fi 自定义 UDP | agent `192.168.31.214:8888`，本地端口 8888 | 正常 ROS2 链路 |
| `microros_uart` | UART0（GPIO43 TX / GPIO44 RX） | 921600，主机发 `MATURO_MICROROS_START` 握手 | 无 Wi-Fi / 低时延场景 |
| `mavlink_udp` | UDP | 端口 14550，广播发现 + 单目标锁定 | QGroundControl / PIX 类工具链 |
| `uart_mavlink` | UART0 | 230400，与日志共用串口 | 串口调试 / 飞控链路 |

另有 ESP-NOW 任务（`espnow_task.cpp`）与 Wi-Fi 配网页（`wifi_provision_task`，SoftAP + HTTP）。MAVLink 路线暴露 `SPD_KP/KI/KD`、`POS_KP/KI/KD` 参数与 `COMMAND_LONG` 自定义指令（相对运动 `USER_2`、PID 更新 `USER_4`）。

## 8. 全流程（从零件到自主导航）

```
① 硬件复现（打板/焊接/采购/3D 打印外壳）
   → ② 固件工程（ESP-IDF + VS Code 扩展，编译烧录）
   → ③ Wi-Fi 配网（SoftAP → STA，agent IP 写入 NVS）
   → ④ micro-ROS 连通（agent ↔ 固件，话题/服务全链路）
   → ⑤ 遥操 + 传感器验证（teleop、RViz、TF 树、里程计/PID 标定）
   → ⑥ SLAM 建图（gmapping / cartographer，保存地图）
   → ⑦ Nav2 自主导航（定位、规划、避障、恢复行为）
   → ⑧ 视觉与交互扩展（WiFi 图传、I²C 手柄、配网页）
   → ⑨ 工程化沉淀（rosbag、文档、作品集、开源协作）
```

## 9. 关键设计决策与权衡（面试常考）

| 决策 | 理由 |
|---|---|
| MCU 侧用 micro-ROS 而非移植完整 ROS2 | ESP32-S3 资源（RAM/Flash）跑不动完整 DDS；micro-ROS 以静态库 + XRCE-DDS 客户端方式接入 |
| 默认 Wi-Fi 自定义 UDP 传输，保留 UART 传输 | UDP 免接线；UART 模式在无路由器/实验室禁无线时可用，且时延更稳 |
| 兼容 MAVLink 双协议 | 复用 QGroundControl 生态调试，MAVLink 消息集成熟（HEARTBEAT/ODOMETRY/OBSTACLE_DISTANCE） |
| 雷达数据两条链路 | 主线：固件解析后直接发 `/scan`（省一个串口设备）；备选：原始串口流经 UDP:8889 → socat PTY → ydlidar 驱动（`xuegeros_demo` 路线，需要额外安装 `ydlidar_ros2_driver`） |
| PID 服务化（`/set_speed_pid`） | 参数在线整定，不重新烧录；写入 NVS 断电保持 |
| 文档仓库用 submodule 引上游 | license 边界 + 可跟随上游更新 + 个人修改可 fork 管理 |

## 10. 事实与推断

- **事实**（本文全部参数）：来自上游 4 个仓库 README / `doc/protocols.md` / 源码，本机 `~/leap-ros-2/src/upstream/*` 可直接核对。
- **推断**：`espnow_task` 的具体用途上游文档未展开；`xuegeros_demo` 中 UDP:8889 的上游发送设备（WiFi 串口模块）未在代码中体现——以固件 `/scan` 主线为准，demo 路线仅作参考。
